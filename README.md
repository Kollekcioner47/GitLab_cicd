# GitLab CI/CD — практический курс
<img width="1536" height="1024" alt="image" src="https://github.com/user-attachments/assets/2ae63e9b-84f8-4802-afa6-e664a8ca6940" />

> **От GitLab CE и первого pipeline до production-деплоя, безопасности и автоматизации**

Практический курс по построению полноценного конвейера **CI/CD в GitLab**: от развёртывания собственного GitLab CE до production-пайплайна с тестированием, анализом безопасности, окружениями, Review Apps, управлением секретами и автоматической реакцией на сбои.

Курс построен вокруг **реального учебного стенда** и последовательного развития нескольких учебных проектов.

---

## О курсе

- **9 лабораторных работ**
- **13 теоретических модулей**
- **~154 слайда** в новой версии презентации
- Практика на **GitLab CE + GitLab Runner**
- Docker, Container Registry, PostgreSQL, FastAPI, Go
- SAST, Trivy, Code Quality
- Review Apps, JUnit и GitLab Pages
- Управление секретами с `sops + age`

Материалы рассчитаны на самостоятельное прохождение на собственном стенде.

---

## Результаты обучения

- устанавливать и настраивать GitLab CE и GitLab Runner на своих машинах;
- писать `.gitlab-ci.yml`: stages, jobs, теги раннеров, артефакты, правила;
- разделять окружения (staging / production) и ставить ручное подтверждение;
- собирать Docker-образы в пайплайне и хранить их в GitLab Container Registry;
- тестировать приложение с реальной базой данных и публиковать отчёты;
- ускорять пайплайн кэшированием зависимостей и слоёв Docker;
- встраивать проверки безопасности (Trivy, SAST, Code Quality) и честно
  оценивать их ограничения;
- деплоить на отдельный целевой сервер и поднимать Review Apps под merge request;
- хранить конфигурацию зашифрованной (sops + age) и публиковать документацию
  через GitLab Pages;
- автоматически реагировать на падения пайплайна.

## Стенд курса

Курс рассчитан на две виртуальные машины под управлением Debian.

| Компонент | Значение |
|---|---|
| Домен GitLab | `https://gitlab.local` (самоподписанный сертификат с SAN) |
| Сервер GitLab | `10.0.2.5` |
| Целевой сервер (app-server) | `10.0.2.6` |
| Container Registry | `gitlab.local:5050` (HTTPS) |
| Теги раннеров | `cd` (shell), `docker` (docker), `app-server` |
| Ветка по умолчанию | `main` |

### Порты приложений

| Приложение / окружение | Порт |
|---|---|
| `simple-site` production (Apache) | 81 |
| `simple-site` staging (Apache, практика 3) | 8081 |
| `simple-site` staging (контейнер, практика 4) | 8085 |
| `simple-site` production (контейнер) | 85 |
| `notes-api` staging | 8088 |
| `mini-crm` staging | 8090 |
| `mini-crm` production | 80 |
| Review Apps (`mini-crm`) | 811–8199 (для merge request № 1–99) |

### Требования к стенду

- Debian (или Ubuntu) — команды установки рассчитаны на `apt`;
- для практик 1–7 достаточно одной ВМ; вторая (`10.0.2.6`) нужна начиная
  с практики 8;
- GitLab CE требователен к ресурсам: на слабой ВМ он будет заметно тормозить;
- в практиках 1 и 8 используются пути вида `/home/engineer`, то есть
  подразумевается пользователь `engineer`;
- доступ в интернет для установки пакетов и скачивания образов.

## Как проходить курс

1. Прочитайте модуль презентации, соответствующий лабораторной (см. карту выше).
2. Выполните лабораторную работу по шагам.
3. Сверьте результат с блоком «Проверка» в конце работы.
4. Переходите к следующей — модули и практики идут по возрастанию сложности.

Рекомендуемый порядок: **1 → 2 → 3 → 4 → 5 → 6 → 7 → 8 → 9**.
Практики 6 и 7 развивают проект `notes-api` из практики 5; практика 9 —
проект `mini-crm` из практики 8.

### Известные ограничения

- Теоретические колоды вынесены в отдельные файлы и **не привязаны к стенду**
  лабораторных (нет адресов, портов и тегов из практик) — это исправляется новой
  презентацией по промптам.
- Вторая ВМ (`10.0.2.6`) появляется только в практике 8; перед её использованием требуется подготовить сервер приложения.
- Отдельные практики содержат токены-плейсхолдеры и учебные значения SMTP —
  перед публикацией стенда проверьте, что реальные токены отозваны.
